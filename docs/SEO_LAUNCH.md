# SEO-запуск «Գրքասեր» на grqaser.am

Будущий основной адрес: **https://grqaser.am**, основной язык — армянский (`/hy`); остальные версии — `/ru` и `/en`. Пока DNS нового домена не готов, работающий предпросмотр на **https://grqaser.digitalize.am** должен использовать собственный canonical (`NEXT_PUBLIC_SITE_URL=https://grqaser.digitalize.am`) и `SITE_INDEXING_ENABLED=false`. Не направлять canonical на недоступный будущий адрес. Это инструкция по запуску, а не подтверждение, что DNS, сертификат и доступ к Search Console уже настроены.

Техническое SEO помогает поисковику обнаружить и понять магазин. Оно не гарантирует первое место, сроки индексации или показ расширенных результатов. Продвижение также зависит от полезности каталога, конкурентности запросов, репутации магазина и поведения реальных покупателей.

## Что реализовано для обхода

- `https://grqaser.am/robots.txt` управляется `SITE_INDEXING_ENABLED`.
- `https://grqaser.am/sitemap.xml` — индекс карт сайта.
- `/sitemaps/static.xml` — главная, каталог, информация и контакты на трёх языках.
- `/sitemaps/books-0.xml`, `/sitemaps/books-1.xml` и далее — реальные книги из публичного каталога API. Каждая часть читает максимум 100 книг одним запросом и содержит максимум 300 языковых URL.
- В sitemap включаются только реально существующие переводы книги и её исходный язык. Язык интерфейса не считается переводом описания. Недоступные в продаже книги сохраняют свои страницы.
- Нет выдуманных товаров, рейтингов, отзывов и даты изменения. `observedAt` — дата наблюдения цены/наличия, а не достоверная дата правки страницы, поэтому она не выдаётся за `lastmod`.
- Ответы XML кэшируются на 5 минут. Тайм-аут API — 10 секунд. Ошибка, неполный ответ или превышение ограничений дают `503` с `Retry-After: 300`, а не ложную пустую карту с `200`.

Карта рассчитана на каталоги больше 50 000 URL. Ограничения протокола проверяются: максимум 50 000 записей и 50 MiB на XML. Один индекс обслуживает до 4 999 900 книг; при большем каталоге необходимо реализовать несколько отдельно подаваемых индексов. Превышение явно завершится ошибкой, а не незаметным пропуском книг. Вложенные sitemap-индексы не использовать. [Официальные требования к sitemap](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).

Пагинация сортируется по названию, с уникальным ID как дополнительным ключом в PostgreSQL. При очень частом массовом обновлении каталога следующий этап — неизменяемые снимки sitemap: независимые запросы не являются единым снимком базы. До этого перепроверять карты после крупных импортов.

## До включения индексации

1. Подтвердить владение `grqaser.am` у регистратора и настроить DNS на сервер магазина. Для текущего сервера целевой IPv4 — `161.97.101.68`. Проверить, что нет старой `AAAA`, ведущей на другой сервер. `www` подключать только при необходимости и перенаправлять на основной адрес.
2. Выпустить действующий TLS-сертификат для нового домена. Проверить HTTPS без игнорирования ошибок сертификата.
3. Убедиться, что приложение действительно обслуживает `grqaser.am`, а API, изображения, авторизация и оформление заявки работают на нём. Проверить допустимые origin, secure-cookie, proxy headers и переменные окружения; не переносить чужие cookie-домены.
4. Заполнить реальный каталог. Пустая витрина и тестовые книги не подходят для продвижения. Проверить цены в AMD, обложки, наличие, языки, условия заказа и реальные контакты.
5. Проверить публичные условия: доставка только по Еревану, её итоговая стоимость, оплата наличными, подтверждение заказа, возвраты и контактные сведения. Не обещать сроки или наличие, которые магазин не обеспечивает.
6. Проверить HTML основных страниц: корректные заголовки, описание, canonical на `https://grqaser.am`, языковые ссылки и структурированные данные без скрытых или недостоверных утверждений.
7. Проверить **`NEXT_PUBLIC_SITE_URL=https://grqaser.am`** при сборке и в окружении веб-приложения. Переменные `NEXT_PUBLIC_*` могут встраиваться во время сборки; после смены адреса нужен новый образ, а не только перезапуск старого.
8. Только после этих проверок установить **`SITE_INDEXING_ENABLED=true`**, **пересобрать образ web** с тем же значением и пересоздать контейнер. Простой restart или изменение только runtime-переменной недостаточны: Next.js фиксирует HTTP-заголовки из `headers()` во время сборки. Compose передаёт флаг и в build args, и в runtime; их значения должны совпадать. По умолчанию индексация выключена: robots запрещает обход, sitemap возвращает `404`, а SEO-слой приложения помечает страницы `noindex`.

Docker-конфигурация, безопасные команды обновления и проверка заголовков описаны в [DEPLOYMENT.md](DEPLOYMENT.md). Не смешивать новый runtime-флаг со старым образом: можно получить открытый robots, но сохранённый при сборке `X-Robots-Tag: noindex`.

`robots.txt` не является защитой персональных данных. Админка и аккаунт требуют настоящей авторизации. После запуска не блокировать обход HTML-страниц только ради `noindex`: иначе поисковик не сможет прочитать эту директиву. В рабочем режиме robots запрещает API, но допускает чтение HTML-директив приватных страниц и поиска. Для уже попавших в индекс тестовых страниц нужен отдельный план удаления; запрет обхода сам по себе не удаляет их. [Правила robots meta](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag).

## Переезд с grqaser.digitalize.am

До готовности DNS и HTTPS нового домена **не включать перенаправление** со старого: иначе работающий магазин станет недоступен.

После проверки нового адреса:

- Сохранить старый DNS и сертификат, настроить постоянный `301` или `308` на такой же путь нового домена, включая параметры запроса.
- Например, `/ru/books/example` должен вести на `https://grqaser.am/ru/books/example`, а не на главную. Не делать цепочки перенаправлений и массовый редирект всех книг на главную.
- Перенаправить HTTP нового домена на HTTPS; выбрать один вариант `www`/без `www`.
- Убедиться, что внутренние ссылки, canonical, языковые альтернативы и sitemap используют только конечный адрес.
- Проверить права на оба ресурса в Google Search Console. Для настоящего переезда использовать инструмент Change of Address, если он применим к подтверждённым ресурсам.
- Сохранять перенаправления не менее года, лучше дольше. Колебания видимости при переезде возможны. [Рекомендации Google по смене адресов](https://developers.google.com/search/docs/crawling-indexing/site-move-with-url-changes).

## Что делает владелец в Google Search Console

1. Добавляет Domain property `grqaser.am` в своём Google-аккаунте.
2. Копирует предоставленную Google TXT-запись в DNS. Не публикует логин, пароль или доступ к аккаунту в коде.
3. После подтверждения отправляет `https://grqaser.am/sitemap.xml`.
4. Проверяет URL главной и нескольких реальных книг через URL Inspection / Live test: доступность, выбранный canonical, robots и отрисованный HTML.
5. При необходимости запрашивает индексацию нескольких важных страниц. Это не обещание немедленной индексации.
6. Следит за Page indexing, Sitemaps, Core Web Vitals, поисковыми запросами, показами и кликами. Ошибки sitemap `503` требуют проверки API, а не повторной отправки пустых карт.

Для URL-prefix property вместо DNS доступна HTML-проверка: полученный именно от Google код можно задать как `GOOGLE_SITE_VERIFICATION`. Поддержан также `YANDEX_SITE_VERIFICATION` для Яндекс Вебмастера. Эти переменные создают meta-теги, но не заменяют действия владельца в поисковом сервисе. Для Domain property нужна DNS-проверка, HTML-тег недостаточен.

Для улучшения выдачи товаров отдельно проверить соответствие правилам Google Merchant Center; создание аккаунта и фида — самостоятельная задача владельца, а не автоматический результат JSON-LD.

## Контент и приоритеты после запуска

- Сначала качественно оформить важные книги: точное издание, ISBN, автор, язык книги, издательство, страницы, понятное описание и актуальная цена. Использовать изображения и тексты, на которые есть необходимые права.
- Добавлять собственные полезные описания и подборки, а не механически копировать весь текст поставщика. Переводы проверять носителем языка. Не создавать сотни одинаковых страниц под города, ключевые слова и фильтры.
- Сейчас query-параметры поиска, сортировки и фильтров не включаются в sitemap. Если нужны индексируемые тематические страницы, сначала создать стабильные URL, уникальный содержательный текст, товары и внутренние ссылки; не включать бесконечные комбинации фильтров.
- Проверять мобильную скорость на реальных страницах с обложками. Приоритет: размер изображений, LCP, отсутствие скачков макета и быстрый ответ API.
- Собирать только настоящие отзывы. Не добавлять вымышленные звёзды, оценки, сертификаты, адрес офлайн-магазина или несуществующие профили.

## Проверки после каждого релиза

```bash
curl -I https://grqaser.am/hy
curl -fsS https://grqaser.am/robots.txt
curl -fsS https://grqaser.am/sitemap.xml
curl -fsS https://grqaser.am/sitemaps/static.xml
# Только если в каталоге есть книги:
curl -fsS https://grqaser.am/sitemaps/books-0.xml
curl -I https://grqaser.digitalize.am/ru
```

Проверить: главная отвечает `200`, старый адрес даёт один постоянный редирект, sitemap содержит настоящий каталог, отсутствующая книга отвечает `404`, личные страницы не индексируются. Затем проверить Product/Book и BreadcrumbList в [Rich Results Test](https://search.google.com/test/rich-results) и [Schema Markup Validator](https://validator.schema.org/). Положительный результат валидатора не гарантирует расширенный сниппет.

Локальные проверки карт сайта:

```bash
cd apps/web
node --test tests/seo-sitemap.test.mjs
```
